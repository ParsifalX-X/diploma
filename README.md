**Общая Цель:** Разработка программного модуля для учета заявок на ремонт климатического оборудования (Дипломная работа) с использованием WinForms, C# и SQL Server, согласно предоставленному макету и техническому заданию.

**Отправная Точка:** Имелся частично рабочий код с проблемами навигации между формами (приложение закрывалось или возвращалось на стартовую форму не по логике) и отсутствием интеграции с базой данных.

**Проделанная Работа:**

1.  **Анализ Требований и Проектирование Базы Данных:**
    *   Проанализированы предоставленные "Описание предметной области" и "Техническое задание".
    *   Определены ключевые сущности: Заявка (`Request`), Заказчик (`Customer`), Сотрудник/Пользователь (`User`), Тип Оборудования (`EquipmentType`), Статус Заявки (`RequestStatus`), Комментарии (`RequestComment`), Комплектующие (`RequestPart`).
    *   Спроектирована структура реляционной базы данных (`ServiceCenterDB`) в SQL Server, включающая 7 таблиц с необходимыми полями, типами данных, первичными (`PK`) и внешними (`FK`) ключами, а также ограничениями (`NOT NULL`, `UNIQUE`, `DEFAULT`). Особое внимание уделено таблице `Users` с полями для логина (`Username`), **хэша пароля** (`PasswordHash`), ФИО, роли и статуса активности.

2.  **Настройка Среды SQL Server:**
    *   Обсуждена и решена необходимость установки **SQL Server Express Edition** и **SQL Server Management Studio (SSMS)**.
    *   Предоставлены пошаговые инструкции по установке и первому подключению к локальному экземпляру SQL Server.
    *   **Решены проблемы с подключением в SSMS:**
        *   Ошибка "Цепочка сертификатов выпущена центром сертификации, не имеющим доверия": Решена путем активации опции **"Trust server certificate"** в параметрах подключения SSMS. Объяснена причина (самоподписанный сертификат).
        *   Ошибка "Свойство Login не было задано": Решена путем выбора правильного типа аутентификации **"Windows Authentication"**.
    *   **Результат:** Успешное подключение к локальному экземпляру SQL Server через SSMS.

3.  **Создание Базы Данных и Таблиц:**
    *   Предоставлены готовые SQL-скрипты для копирования и выполнения в SSMS:
        *   Скрипт для создания базы данных `ServiceCenterDB`.
        *   Скрипт для последовательного создания всех 7 таблиц (`EquipmentTypes`, `RequestStatuses`, `Users`, `Customers`, `Requests`, `RequestComments`, `RequestParts`) с правильными связями (`FOREIGN KEY`).
    *   Подтверждено успешное создание базы данных и таблиц.

4.  **Начальное Заполнение Данных:**
    *   Предоставлен SQL-скрипт для заполнения справочников (`RequestStatuses`, `EquipmentTypes`) и создания **тестовых пользователей** (`admin`, `technician1`, `operator1`).
    *   **Критически важный момент:** Подчеркнуто, что первоначально в скрипте пароли для тестовых пользователей были вставлены **в виде простого текста** (например, `'AdminPassword123'`) во временных целях, что **небезопасно** и **несовместимо** с последующей реализацией хэширования.

5.  **Настройка Проекта WinForms (`WFA_libUI`):**
    *   Создан (или подтверждено наличие) проект WinForms `WFA_libUI`.
    *   **Настроено подключение к БД из приложения:**
        *   Строка подключения к `ServiceCenterDB` добавлена в файл `App.config` под именем `DefaultConnection`. Строка включает необходимые параметры для подключения к локальному SQL Server Express (`Server=...;Database=ServiceCenterDB;Integrated Security=True;TrustServerCertificate=True;`). *Конкретное имя сервера было заменено на `...`, но в твоем `App.config` оно должно быть правильным.*
        *   Объяснена необходимость параметра `TrustServerCertificate=True` для подключения к локальному SQL Server Express из C# кода.

6.  **Настройка Доступа к Данным (Entity Framework Core):**
    *   **Выбрана технология:** Entity Framework Core (EF Core) как ORM для упрощения взаимодействия с базой данных по сравнению с ручным ADO.NET.
    *   **Решены проблемы с версиями EF Core:**
        *   Первоначальная попытка установить последнюю версию EF Core (9.x) провалилась из-за несовместимости с **.NET Framework 4.7.2**.
        *   Попытка установить EF Core 5.0.17 также не удалась.
        *   **Успешно установлена совместимая версия: EF Core 3.1.32** (`Microsoft.EntityFrameworkCore.SqlServer` и `Microsoft.EntityFrameworkCore.Tools`).
    *   **Созданы необходимые классы EF Core:**
        *   Создан класс-сущность `User.cs`, точно отражающий структуру таблицы `Users`.
        *   Создан класс контекста базы данных `ServiceCenterDbContext.cs`, наследуемый от `DbContext`, содержащий `DbSet<User>` для доступа к таблице пользователей и настроенный на использование строки подключения `DefaultConnection` из `App.config`.
    *   Подтверждено, что файлы `User.cs` и `ServiceCenterDbContext.cs` созданы в корне проекта `WFA_libUI` и имеют правильное пространство имен `namespace WFA_libUI;`.

7.  **Реализация Аутентификации и Регистрации (`FormLogInSign`):**
    *   **Установлен пакет для хэширования:** `BCrypt.Net-Next 4.0.3`.
    *   **Полностью переписан код `FormLogInSign.cs`:**
        *   Удалена вся "захардкоженная" логика.
        *   Реализовано взаимодействие с базой данных через `ServiceCenterDbContext`.
        *   **Регистрация:** Добавлена валидация полей, проверка уникальности `Username`, **правильное хэширование пароля** с использованием `BCrypt.Net.BCrypt.HashPassword`, создание нового объекта `User` и сохранение его в БД через `db.SaveChanges()`.
        *   **Вход:** Реализован поиск пользователя по `Username`, проверка статуса `IsActive`, **правильная проверка хэша пароля** с использованием `BCrypt.Net.BCrypt.Verify`.
    *   **Решены проблемы компиляции:**
        *   Устранены ошибки, связанные с отсутствием файлов `User.cs` и `ServiceCenterDbContext.cs` путем их создания.
        *   Устранены ошибки, связанные с отсутствием `using` директив и ссылок на сборки (`System.Linq`, `BCrypt.Net`, `WFA_libUI`, `System.Configuration`).
        *   **Решена проблема с методами `BCrypt.HashPassword` и `BCrypt.Verify`:** Использовано **явное указание пространства имен** (`BCrypt.Net.BCrypt.HashPassword()` и `BCrypt.Net.BCrypt.Verify()`) для решения конфликта или проблемы с кэшем.
    *   **Решена проблема "Invalid salt version" при входе:** Выяснено, что в БД для пользователя `admin` хранился текстовый пароль. Проблема решена путем удаления старой записи `admin` из БД и **повторной регистрации `admin` через форму приложения**, чтобы сохранить корректный BCrypt-хэш.

8.  **Коррекция Навигации:**
    *   В `FormLogInSign` реализована правильная логика перехода: при успехе устанавливается `this.DialogResult = DialogResult.OK`, текущая форма закрывается (`this.Close()`), **затем** показывается следующая форма (`userForm.Show()` / `adminForm.Show()`).
    *   Обсуждена и исправлена логика навигации в `FormMainPage` (использование `ShowDialog()` для `FormLogInSign` и проверка `DialogResult`).
    *   **Обнаружена и указана логическая ошибка в `FormUser`:** Строка `openForm(new FormMainPage());` некорректна и должна быть удалена/закомментирована.

9.  **Обсуждение Статичности Форм:**
    *   Обсуждены способы сделать формы `FormUser` и `FormAdmin` неперемещаемыми и не изменяемыми по размеру (через `FormBorderStyle`, удаление кода перетаскивания, удаление кнопок `MinimizeBox`/`MaximizeBox`).

**Текущий Статус и Актуальная Проблема:**

*   **УСПЕХ:** Проект компилируется без ошибок.
*   **УСПЕХ:** Регистрация нового пользователя работает, данные корректно хэшируются и сохраняются в базе данных SQL Server.
*   **УСПЕХ:** Вход в систему для зарегистрированных пользователей (включая 'admin' после перерегистрации) работает, проверка пароля с использованием BCrypt проходит успешно.
*   **ПРОБЛЕМА / БЛОКЕР:** Несмотря на успешную аутентификацию/регистрацию и отсутствие ошибок во время выполнения в `FormLogInSign`, **переход на следующую форму (`FormUser` или `FormAdmin`) НЕ ПРОИСХОДИТ.** Код в `FormLogInSign` доходит до вызова `OpenUserFormAndClose()` или `OpenAdminFormAndClose()`, но сама форма не появляется.

**Непосредственные Следующие Шаги (Диагностика Блокера):**

1.  **Целевая Отладка Конструкторов:** Необходимо запустить приложение в режиме отладки (F5) и поставить точки останова **внутри** методов `OpenUserFormAndClose`/`OpenAdminFormAndClose` (на строках `new Form...()`, `this.Close()`, `*.Show()`) и **внутри конструкторов** `FormUser`/`FormAdmin` (на строке `InitializeComponent();`).
2.  **Пошаговое Выполнение (F11/F10):** Тщательно проследить с помощью **F11 (Step Into)**, входит ли выполнение в конструктор целевой формы при вызове `new Form...()`. Затем с помощью **F10 (Step Over)** выполнить строку `InitializeComponent();` и посмотреть, не возникает ли на этом этапе необработанное исключение (которое может молча прервать выполнение без видимого сообщения об ошибке) или зависание.
3.  **Анализ Результатов Отладки:** Определить точную строку кода в конструкторе `FormUser` или `FormAdmin` (скорее всего, внутри или сразу после `InitializeComponent()`), на которой прерывается или "зависает" процесс создания/отображения формы.

**Итог Итога:** Проделана огромная работа по настройке окружения, созданию базы данных, интеграции EF Core, реализации безопасной аутентификации и исправлению навигации. Основной функционал входа/регистрации с точки зрения данных работает. Осталась критическая проблема с отображением следующей формы после успешного входа/регистрации, которая требует детальной отладки конструкторов `FormUser` и `FormAdmin`.
